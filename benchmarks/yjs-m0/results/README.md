# M0 baseline results

These reports measure the required Grain baseline at commit `89d94625e12c0dd8e5db7728ad3a41de3445bc2d` with `yjs@13.6.33`. Fixture text and Grain IDs use seed `520052`. Yjs client IDs are generated by Yjs and recorded as observed values.

## Core profile

[core.json](./core.json) contains two fresh-process runs for all seven core fixtures. Each distribution has 25 warm-up and 200 measured operations. The JSON includes per-process p50/p95, dispersion, native operation counters, update and receipt bytes, checkpoint sizes, structures, ownership summaries, and heap/RSS observations.

The table reports the median across processes of each process's `prepareThroughPublish` p50 and p95. `p50 MAD` is the median absolute deviation across the two process p50 values. All times are milliseconds.

| Fixture                   |      p50 |      p95 | p50 MAD |
| ------------------------- | -------: | -------: | ------: |
| `paragraphs-10`           |    5.070 |    8.077 |   0.001 |
| `paragraphs-150`          |   46.622 |   81.298 |   0.081 |
| `paragraphs-1000`         |  391.553 |  679.387 |   3.906 |
| `paragraphs-5000`         | 2604.965 | 4382.348 |   6.237 |
| `long-tape-16384`         |    2.729 |    4.501 |   0.006 |
| `wide-list-1000`          |  524.875 |  839.684 |   0.024 |
| `fragmented-ownership-32` |   11.479 |   16.420 |   0.216 |

The wide-list structural move counter sample recorded 2,004 map sets, including 2,000 unchanged map sets; its accepted update was 50,611 bytes, receipt was 75,257 bytes, and checkpoint growth was 50,592 bytes. This is a single untimed counter sample, separate from the 200-operation timing distribution.

These are baseline observations from the runner, not portable performance claims. The proposal's engineering budgets apply to later implementation milestones.

## Environment and command

The core report records the exact invocation and environment. It ran on Node.js `v26.13.0`, npm `12.2.1`, Linux x64 (`6.17.7-300.fc43.x86_64`), and an AMD Ryzen 9 5900X with 24 logical CPUs. This is not a pinned performance-worker result.

```sh
npm run bench:yjs-m0 -- --profile core --runs 2 --output benchmarks/yjs-m0/results/core.json
```

Ownership snapshots group tapes by `spanCount` and `ownerCount`, with `tapeCount` giving the number of tapes in each group. This preserves the ownership distribution without repeating fixture node IDs thousands of times. The report's timings and operation counts are unchanged by this compaction.
